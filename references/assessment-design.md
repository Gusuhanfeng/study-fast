# 应试与实操分支

## 题目来源与覆盖

先对照已明确范围、作业、课件例题和展示试题，去重并建立内部题目矩阵：题型、知识点、认知动作、难度、来源、答案核验。分别记录原材料题 source、合理变式 variant、推测题 inferred。qa 可使用 origin 与 evidence_ids 关联内部账本；这些字段不渲染。

试卷照片只依据能辨认的内容，缺失条件先核对其它资料。无法恢复时不得编造“原题”；可改为条件完整的合成变式并在内部记录。用户说题型不会变作为 USER_STATED，不升级成已核验事实。

推测题围绕已授内容及已见命题方式：改变参数或边界、逆向求解、比较方法、补全算法、纠错、推导或解释条件。每个新增题型须有依据；避免随机扩展不相关章节，也避免仅换数字导致重复堆量。判断覆盖而非追求题目数量。

## 内容与答案

题库按题型组织，面试题按能力或环节组织，不按教材章节重复编排。纯题库仅题目和答案，可有总标题与题型标题。必要假设和不确定答案边界属于内容，不应因去备注而隐去。

每道题必须有答案。计算题核验数值与中间步骤；推导题检查假设与维度；算法题检查初始化、更新顺序、停止条件；编程题检查可运行性、复杂度和边界。选择题唯一性、开放题可接受解法、题干与答案一致性均须检查。自定评分点不能称为教师官方评分标准。

## 配置

qa 的 question 和 answer 为非空文字；复杂内容用 question_blocks / answer_blocks，每项允许 paragraph、table、equation、code。equation 使用 OMML 的 m:oMath 根节点；只接收数学命名空间内容，不接收文档XML、DTD或外部实体。示例见 examples/question-bank.json。先构建真实分式、上下标、矩阵结构，再验证渲染；不要把LaTeX源字符串当排版结果。

layout.answer_mode 可为 adjacent 或 separate，二者都输出答案。模拟卷另需 duration_minutes、total_points，每个qa的points必须相加等于总分。试卷包含答案分部，不会产生无答案的占位文件。需要单独试题文件时在核验后的成品上另行导出，并保留对应答案。

## 面试与实操

技术题与岗位证据对应；行为题用真实经历或诚实的回答框架。需要代码时给出接口、约束、测试及答案；系统设计明确负载和故障假设。不会因为出现“面试”就套固定算法清单。

内部记录执行环境和结果，不在分享正文插入制作日志。任务本身要求运行结果时呈现真实结果，未运行与运行通过严格区分。
