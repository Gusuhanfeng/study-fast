# 隐私与证据规则

## 数据最小化

先盘点，后读取。只读取与当前学习、考试、岗位、工作或会议目标直接相关的材料。私人目录可能包含凭据、通信、授权受限内容和无关个人文件，不得无差别复制或扫描。

个人简历、已填写资料、私人代码、会议邀请、未公开报告、任务配置、生成文档和渲染结果必须保存在本技能目录之外。

## 默认脱敏

所有生成文档默认使用“学习者”“候选人”“汇报人”“你”或无主语表达，不写入：

- 真实姓名、邮箱、电话、地址、证件号；
- 用户名、主目录、本机绝对路径；
- 非必要的学校、雇主、客户和同事标识；
- 私人仓库、云盘、内网和会议链接；
- API key、Token、Cookie、密码、许可证服务器和 `.env` 内容；
- 未授权的客户、患者、应聘者、数据集或研究对象标识；
- 文档作者、最后修改者、自定义属性、批注作者和修订会话元数据。

任务配置中的 `privacy.prohibited_terms` 应列出当前材料里绝不能进入输出的姓名、账号、组织、项目代号和私人域名。该配置属于任务私有文件，不能保存进技能目录。

## 扫描模式

- `balanced` 为默认模式：真实电话号码、私钥、疑似非占位密钥和禁止词阻止生成；邮箱、绝对路径、UNC 路径和内网地址作为警告，要求人工复核。
- `strict` 将上述警告也升级为阻止项，适合包含个人、客户、患者或未公开项目材料的任务。
- `YOUR_TOKEN`、`<API_KEY>`、`${TOKEN}`、`PLACEHOLDER` 和 `REDACTED` 等明显占位符不作为真实密钥阻止。占位符豁免不适用于私钥块和用户指定禁止词。

扫描是候选检测，不是匿名证明。技术教学中出现的示例邮箱和路径可能是合理内容；真实个人信息也可能不符合固定正则，因此最终仍需对照输入人工复核。

## 证据等级

- `VERIFIED`：由当前输入中的代码、日志、报告、数据、证书、正式文档或可靠当前来源支持。
- `USER_STATED`：用户明确陈述但尚未独立检查。
- `INFERRED`：基于材料的合理解释，必须标为推断。
- `UNKNOWN`：缺失、互相矛盾、无法访问或无法确认。

岗位匹配可额外使用：`DIRECT`（直接证据）、`ADJACENT`（相邻能力）、`GAP`（无证据）。这些标签不能替代证据等级。

## 真实性门禁

不得为了形成完整故事而制造经历、贡献、指标、成绩、研究结果、面试流程、生产部署、会议决定或工作权限。对尚未完成的学习、测试、运行、实验和评审使用计划或待验证措辞。

数值结论至少需要值、定义、比较基线、时间或版本以及来源。无法满足时保留原始观察并标 `UNKNOWN`，不要升级为成果声明。

## 交付前检查

同时检查正文和 DOCX 元数据。自动扫描只能发现候选问题，不能证明完全匿名；还需对照当前输入人工核验名称、路径、链接和上下文可识别信息。
